# coin-merge：抖音小游戏发布评估

查询日期：2026-10-20（北京时间）。对象：当前 Godot 4.7.2、Compatibility、GDScript、750×1334 竖屏工程。结论依据为本地代码、直接读取的抖音官方文档、Godot 4.7 官方文档及明确注明的第三方插件资料。本评估阶段仅修改文档，没有安装插件、调整引擎版本、生成发布包、注册应用或上传提审；后续图片与字体换皮进展已在本文对应条目更新。

## 1. 发布目标与运行方式

**发布目标为抖音小游戏：先完成 Godot 运行验证，再补平台能力和提审材料。现有玩法可以保留，不能把标准 Godot HTML5 导出直接视为抖音小游戏包。**

抖音小游戏发布工程由 `game.js`、`game.json`、`project.config.json`、适配后的Godot运行时及游戏资源组成，通过 `tt` API 接入宿主能力。已有第三方Godot导出方案，但本工程4.7.2与插件已验证4.6.1存在版本差距，必须先验证。

官方小游戏环境是绑定宿主能力的 JavaScript VM，**没有浏览器的 DOM/BOM，也没有原生 `window`**；标准 Godot Web 导出依赖浏览器的 WebAssembly 和 WebGL 2.0。[开发指南](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/dev-guide/bytedance-mini-game)、[Godot Web导出](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html)共同说明需要适配，但不能据此断言Godot无法进入抖音。

## 2. 可保留 Godot，但先解决版本与运行时

### 2.1 已找到的候选导出器

第三方开源项目 [AnranS/godot_for_minigame](https://github.com/AnranS/godot_for_minigame) 明确提供抖音小游戏导出、适配后的引擎与平台SDK。它不是抖音或Godot官方发布的导出器。

截至查询时，GitHub Releases 的最新正式发布是 **v0.2.1，2026-08-02发布**，见[正式Release](https://github.com/AnranS/godot_for_minigame/releases/tag/v0.2.1)。该版本的[支持矩阵](https://github.com/AnranS/godot_for_minigame/blob/v0.2.1/support-matrix.json)只列出以下已验证身份：

| 项目 | 插件v0.2.1已验证值 | 本项目 |
|---|---|---|
| Godot | 4.6.1.stable，提交 `14d19694e0c8` | 4.7.2.stable，提交 `ed1daf0bf` |
| Emscripten | 4.0.3 | 尚未建立小游戏编译工具链 |
| 模板 | `2d_full` / release / revision 1，要求精确引擎身份 | 尚无匹配模板 |
| 抖音 | 自动导出/包结构检查 | 尚未在抖音IDE或真机运行 |

仓库main的README/支持矩阵已经写到0.3.0，不能把main文档等同于已发布的0.2.1，也不能把自动导出检查称为抖音真机认证。

建议先做一个独立的最小验证工程，选择下列一条：

1. **保留4.7.2：**参照插件的[自定义引擎模板说明](https://github.com/AnranS/godot_for_minigame/blob/v0.2.1/docs/USAGE_zh.md#12-编译自定义引擎模板)，构建与4.7.2精确匹配的小游戏模板并完成平台验证。构建成功仍不能替代真机验证。
2. **使用已验证版本：**在隔离副本中测试本项目能否迁移到4.6.1，核对场景资源、GDScript、着色器、字体及全部玩法回归。不要直接用4.6.1模板装入4.7.2工程并假定兼容。

只有这两条都不可接受或验证失败，再评估迁移Cocos等引擎；现阶段没有依据要求把已有游戏全部重写。

### 2.2 需要验证的底层能力

官方[TTWebAssembly](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/framework/basic-function/web-assembly)自基础库3.7.0.0提供，加载包内 `*.wasm.br`，其编译/实例化接口接收包内路径；iOS目前不支持SIMD等提案特性。插件通过适配后的WASM、Emscripten胶水、画布、音频、输入、网络和文件系统启动Godot，标准HTML外壳不能代替这些工作。

首次验证至少要实际跑通：启动、三槽可点击棋盘、隐藏翻面、2D粒子/三个现有着色器、中文字体、音效、触摸、文件保存、退出重进。随后再加载正式首关和208槽大盘。优先使用单线程且与宿主WASM特性相容的模板，不能只检查开发者工具里是否有首帧。

## 3. 本项目需要补的工程工作

| 优先级 | 工作 | 现状与完成标准 |
|---|---|---|
| P0 | 确认导出路线与匹配模板 | 尚无抖音工程。按第2节完成IDE和Android/iOS真机最小验证，再承诺完整移植。 |
| P0 | 核实美术、音效与品牌的发布权利 | 图片与字体已完成陶瓷换皮：104 项旧图片中 103 项替换、1 项旧数字图集移除，字体改用 OFL 子集；详见[实际引用图片与换皮清单](实际引用图片与换皮清单.md)。仍保留 14 种原作音效（初次统计漏计 placeCoin 绑定回调），需取得覆盖发行的授权或重制，并核实名称、品牌与其他发布材料。 |
| P1 | 发布预设与资源过滤 | 尚无 `export_presets.cfg`、`game.js`、`game.json`、`project.config.json`。建立生产预设、竖屏、AppID及版本配置；只打包运行资源，排除取证数据、测试、工具和预览。部分参考目录已有 `.gdignore`，仍需检查最终清单。 |
| P1 | 清理开发期自动加载 | `project.godot` 仍自动加载 `_mcp_game_helper`。发布构建应禁用该开发辅助入口，再检查包内插件和资源。 |
| P1 | 统一平台桥接 | 当前只有YouTube挑战插屏桥接；新增抖音平台实现，将宿主能力检测、广告、生命周期、振动、存储和复访接入统一接口。现有 `window.ytgame`、`navigator.vibrate` 检测不能代表 `tt` 环境能力。 |
| P1 | 激励广告与插屏（若做广告变现） | 开通流量主、创建广告位并接SDK。把普通奖励槽和后两次救援由默认放行改为完成广告后发奖；取消/失败不发奖、不扣次数，防重复回调。普通祝贺/失败重试与挑战完成插屏按产品配置接入。 |
| P1 | 暂停、音频和挑战计时 | 接宿主 `tt.onHide` / `tt.onShow`；离开、切后台、广告时保存并暂停相应计时/音频，回来恢复。现有应用暂停通知只保存文件，没有完成宿主暂停链路。避免与适配器重复计算或重复恢复。 |
| P1 | 持久化落盘保证 | 本地使用 `FileAccess`、`ConfigFile`、临时文件与重命名。验证适配器完整支持，并在关键进度、退后台时完成宿主持久化。不能把“内存文件写成功”当作小游戏进程终止后仍已保存。 |
| P1 | 官方必接的侧边栏复访 | [必接能力](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/guide/minigame/essential-skills)明确所有小游戏必须接入。当前无入口、场景识别或平台对接；按最新宿主支持情况与后台验收要求补齐。 |
| P1 | 中文字体、屏幕与启动反馈 | 已提供 OFL 授权的 Noto Sans SC 子集并关闭系统字体回退，本地中英文无缺字；抖音运行时的字体渲染仍需真机验证。检查安全区、刘海、返回手势、长宽比；增加本产品的加载进度、失败提示和重试，不必复用原工作室Logo。 |
| P1 | 修复并验收已有流程问题 | 当前挑战流程77项中有1项锁关提示X关闭检查失败，需定位交互/测试时序并补验收。全盘触摸、设置、重玩、切盘中退出和恢复都应在抖音真机复测。 |
| P1 | 适龄、健康提示及隐私展示 | 按官方自审要求增加相应启动信息和用户可查看的政策，按实际使用的SDK/API说明数据处理；结合平台机制落实未成年人保护，不能仅因本游戏是单机就推断全部免除。 |
| 按产品需要 | 登录、跨设备云存档、分享/录屏、排行 | 本地玩法无需为了发布而新增付费、排行榜或金币消费。若要云存档，再接平台登录与后端/抖音云、存档迁移和冲突策略；分享/录屏需实际接入，不能把当前返回选关的stub视为真实分享。 |

**存档特别注意：**插件v0.2.1[文档第10节](https://github.com/AnranS/godot_for_minigame/blob/v0.2.1/docs/USAGE_zh.md#10-本地存储与云端同步)描述的是每5秒从虚拟文件系统同步宿主存储，没有开放正式的手动flush API；本项目每次动作写文件也不能消除这个窗口。main文档已有不同描述，采用哪一个版本必须核对实际代码并验证退后台/强杀恢复。

抖音发布不要求先补齐原作14语种或YouTube云存档，也不要求新增原版入口关闭的收集、皮肤、排行榜。优先补抖音运行、存储、生命周期、必接能力及发布材料。

## 4. 包体、启动与资源限制

按查询到的官方[开发指南“代码包限制”](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/dev-guide/bytedance-mini-game)：

| 类型 | 当前文档限制 |
|---|---|
| 普通非分包小游戏 | 总大小不超过20MB |
| 分包小游戏 | 整体不超过20MB；主包不超过4MB；单个分包不超过20MB |
| 开放数据域 | 文件/目录不超过4MB |

因此不能统一写成“整个游戏只能4MB”，也不能认为多建分包就能无限扩大总包。提审前还应核对实际IDE和当前后台限制。

候选插件v0.2.1把WASM和单个PCK放进 `engine` 分包，资源PCK改名为 `godot.zip`；改名不表示它自动变成了压缩ZIP。其额外 `subpacks` 目录是预留，文档说明尚无受管多PCK输入。因此需要量出本项目的主包、引擎分包和总包；超限时先过滤资源、压缩/裁剪模板和纹理，再评估扩展分包/资源下载。不能直接手改插件受管理的导出目录而假定后续可重复导出。

当前没有生成抖音包，不能用源码目录大小推断上传包大小或保证已满足限额。100关配置已有运行时嵌入，导出不需要带完整REA取证目录。

## 5. 入驻、资质及提交审核

1. **平台账号与应用：**按[注册与入驻](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/guide/minigame/register)完成主体认证；广告服务还涉及主体资质与对公验证。创建小游戏、获取AppID和配置开发成员。
2. **名称及权利材料：**按[资质规范](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/operation1/norms/credential-norms-for-mini-game)准备真实有效的软件著作权、授权关系及相应材料。名称、软著、版号、运营主体之间的要求要分别核对，不能用原游戏的资质替代本项目资质。
3. **小游戏作品备案与ICP：**按[小游戏备案申报](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/guide/minigame/game-filing-application-works)和后台ICP核准流程办理。官方说明已有版号批文的游戏无需重复申请该作品备案；待上线游戏的作品备案由平台在基本信息和版本均审核通过后申报。作品备案、ICP备案、游戏版号是不同事项，不应互相替代。
4. **IAA/IAP区分：**本游戏现有玩法适合先评估广告模式。官方[发布指引](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/guide/minigame/release)要求内购开通提交完整资质，并明确提及版号；不要把这一条扩写成“任何单机广告小游戏都一律同样申请”，也不要断言没有内购就免除其他资质。
5. **内容自审与未成年人保护：**完成[自审自查](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/operation1/norms/specifications)，包括音乐/场景版权、实际适用的批准/登记信息、健康游戏忠告和适龄提示等。官方[防沉迷渠道绑定指引](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/guide/minigame/realnameauthentication)特别要求已获版号的在运营游戏绑定渠道并授权实名/数据上报；按本应用实际类型确认平台和开发者各自承担的部分，不应另行随意采集玩家身份证信息。
6. **隐私及网络配置：**在后台完善本游戏的隐私政策和实际SDK/API用途。若使用服务器或远端资源，按[版本提审指引](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/guide/minigame/examineguide)分别配置request、socket、uploadFile、downloadFile安全域名，使用HTTPS/WSS。
7. **提交与发布：**IDE上传测试版本、真机验证、准备3张实际游戏截图后提审。当前指引说明首次上线有QA回归，且自2026-04-20起符合条件的合作App会一并审核；不能只在一个宿主上测试。通过审核后发布，再配置搜索关键词、分享素材及所需变现能力。

当前图片已换为本轮生成及本地绘制资源，字体按 OFL 分发；仍使用的 14 种音效来自原作发布包，尚未看到覆盖本项目发行的音效授权材料，发布前仍需授权或重制。官方[自审标准](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/operation1/norms/examine-verify)及上述自审自查规则均涉及第三方版权与侵权内容。

## 7. 查询边界

- 官方正文通过HTTPS直接读取，并由Context7交叉查询Godot4.7导出文档。遇到只返回导航壳的旧API链接，未把它当作已读取的具体API行为证据；广告/生命周期的方法名可在当前[JavaScript API总览](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/api/javascript-api/overview)核对，实施时仍需读取对应最新API说明。
- 插件Release及支持矩阵是第三方作者声明与自动化检查范围，不是本项目实测结果；没有安装或执行下载的插件。
- 官方条款、包体限制、能力开放范围可能更新；最终以实际AppID控制台、目标宿主和提交时规则为准。尚未检查用户账号、授权材料、资质和真机设备。
